# 一、项目定位与最终目标

本轮不是普通美化，而是一次完整的产品体验重构：外观焕新、交互可预测、个人记录可靠、资料与筛选可信。

目标用户是以遥控器操作的中文电视用户。核心任务限定为：挑选影片、按条件找片、查看详情、播放与选集、继续观看、收藏、维护资源和基础设置。

最重要的成功标准：用户再次回来，能找到上次的作品与位置；选择某个年份，结果确实有该年份依据；网络或来源出问题，不抹掉用户自己的记录。

## 1.1 需求优先级

| 编号 | 开发目标 | 优先级 | 成功判据 |
| --- | --- | --- | --- |
| G01 | 全中文、无软件标题和品牌露出 | 必做 | 所有应用自有界面及状态完成文案与视觉审计 |
| G02 | 删除设备信息、诊断与调试展示 | 必做 | 生产包不存在诊断采集、分享入口和相关残留路由 |
| G03 | 全新视觉、原创图标、全套状态设计 | 必做 | 核心页面和异常状态均使用同一设计系统 |
| G04 | 遥控器操作、焦点与动画统一 | 必做 | 基础方向键、确认、返回可完成全部核心任务，无焦点丢失 |
| G05 | 页面、筛选、焦点及观看进度持久化 | 必做、数据安全关口 | 正常返回、重启、进程回收等场景按规格恢复 |
| G06 | 继续观看、历史、收藏独立且一致 | 必做 | 删除语义清楚，跨页面一致，断网可浏览个人记录 |
| G07 | 多来源统一数据层与稳定作品身份 | 必做 | 关联有依据、字段可追溯、不覆盖来源与版本差异 |
| G08 | 分类、国家／地区、类型和年份严格筛选 | 必做 | 无静默放宽，支持老年份，资料不足有真实状态 |
| G09 | 一键检测、订阅与有效配置维护 | 流程必做；默认资源接通有条件 | 真实目录可用才报订阅成功；失败保留有效配置 |
| G10 | 性能、低配置适配、升级不丢数据 | 必做、发布关口 | 发布配置性能证据和升级保留数据证据齐全 |
| G11 | 保存筛选、手动备份、睡眠停止等体验增强 | 本轮增强 | 分项测试通过，不牺牲必做目标 |
| G12 | 追更、字幕音轨、外部资料补全 | 有条件增强 | 有真实数据或实际播放能力时呈现，缺失时不伪装 |

必做项不能因时间或资源压力被“完成界面”替代。有条件项须报告真实状态：未满足前置条件、已实现框架、已接通验证，三者不得混淆。

## 1.2 明确不做

不恢复此前移除的电视打字搜索；不做强制账号、社交、积分、广告推荐墙、付费商业体系；不承诺全网资源覆盖；不靠模型猜电影年份、国家或类型；不承诺全设备恒定帧率和任意断电下零数据丢失；不在首轮重写播放器内核、引入复杂云同步或搭建中心化全网采集服务。

多用户档案、跨设备同步、视频离线下载、外部资料库大规模接入列为后续独立范围，本轮只避免数据结构将未来扩展堵死。

# 三、界面、文案与原创图标规格

## 3.1 页面信息架构

导航基线为“首页、片库、我的收藏、最近观看、设置”。这是实施建议，进入视觉冻结时允许减少重复导航，但所有入口须可发现，不能用只含图标的隐蔽入口代替中文标签。

| 页面 | 核心任务 | 必交付内容 |
| --- | --- | --- |
| 首次使用 | 快速接入和理解状态 | 中文引导、一键检测、真实空目录状态、手机配置备用入口 |
| 首页 | 继续观看与轻量浏览 | 续播主入口、真实内容栏、无记录与无来源状态 |
| 片库 | 分类和筛选 | 华语范围、国家／地区、类型、年份、排序、覆盖说明 |
| 详情 | 决定是否观看 | 真实元信息、播放／续播、选集、收藏、资料缺失降级 |
| 播放 | 观看与必要控制 | 进度、暂停、选集、线路、错误恢复、播放设置 |
| 我的收藏 | 保留主动选择 | 收藏列表、稳定排序、取消与撤销、资源失效状态 |
| 最近观看 | 找回看过的作品 | 历史聚合、逐集进度、移除与删除范围说明 |
| 设置 | 不费力地维护应用 | 资源订阅、播放与显示偏好、记录与备份、更新和许可 |

应用内部不出现“极简影院”“Cinema TV”等软件标题、品牌标记或水印。功能标题和影片名称继续保留。版本号仅按需在更新／许可页面以“版本 0.x.x”展示，不常驻首页；平台级安装名称与第三方许可保留必要身份信息。

所有自有交互文案为中文，错误码翻译成可操作说明。原始网络异常、类名、设备型号、IP 和栈信息不出现在普通界面。来源提供的作品原名不编造译名；中文译名缺失时使用真实原名，界面标签仍为中文。海报和视频本身的原始文字不属于应用可任意改写的界面文案。

## 3.2 视觉系统

采用已认可的暗色、内容优先、少量暖色强调方向。重新定义布局、字号层级、间距、圆角、遮罩、焦点与转场，不保留旧版结构只改色。

统一设计尺寸与 `TvMetrics` 的映射，不能同时混用屏幕像素、逻辑尺寸与旧缩放值。提供普通和大字布局，测试长中文标题、长剧集名称、长来源名称与高字号。

有可靠横图使用横图；只有竖海报时保留竖图构图；缺图时使用统一占位。不得用假评分、假清晰度、假热度或默认勾选状态装饰页面。完整业务控件由原生代码实现，不把概念图当作可交互页面铺上去。

## 3.3 原创图标

交付导航、播放、暂停、快进退、前后集、选集、收藏、历史、筛选、排序、线路、订阅、刷新、字幕、音轨、睡眠、设置、清理、备份、恢复、帮助、重试等实际用到的图标。

图标采用统一 24 单位母版网格，并提供适合电视显示的光学修正版本；笔画与圆角采用统一 token，最终数值在设计冻结时确定。常见播放与暂停语义保留，原创体现在具体路径、比例与整套语言，而不是制造难以辨认的新符号。

交付可编辑 SVG 源文件、Compose ImageVector 或 Android 矢量实现、中文无障碍名称、使用与状态对照表。默认／聚焦／按下／选中／不可用状态统一；状态颜色和动画尽量由组件表达，不为每个状态生成一张不可编辑位图。

# 四、遥控器、焦点和动效规格

## 4.1 基础规则

所有核心操作仅用方向键、确认键、返回键完成；菜单键和长按是捷径，不是唯一入口。方向键允许连续移动；确认与返回需要按物理按键周期去重；长按触发时不得先执行一次短按动作。

现有播放键位与新控制面板分别定义状态表。保留现有纯播放状态的左右进退、上下换集习惯；控制面板打开后，方向键用于操作控件。不能在视觉改造中未提示地改变键位含义。

返回只关闭当前最上层操作层；在页面之间回到真实来源路径；最终允许退出至系统，不增加退出确认或无限循环。破坏性数据清理的确认不受此限制。

## 4.2 焦点规则

- 同一操作上下文只有一个明确焦点；“已选中”和“当前聚焦”视觉上不同。
- 弹层打开后禁止背景接收焦点，关闭后恢复触发控件。
- 列表恢复基于稳定作品 ID 与锚点，不只记下标。
- 恢复等待数据和布局就绪，不使用固定延迟作为唯一同步机制。
- 用户在恢复完成前主动操作时，取消迟到的焦点恢复。
- 图片加载、订阅刷新、数据补全不抢焦点、不重排正在浏览的列表。
- 原目标消失时按“相邻有效项 → 当前栏入口 → 页面默认控件”回退，并避免滚到不相关内容。

## 4.3 初始动效参数

这些数值为项目初始设计预算，不是现有实测成绩：焦点变化 120—180 毫秒，页面和面板过渡 180—240 毫秒，背景更换在焦点稳定后执行。焦点缩放以轻微可辨认为准，避免大范围弹跳。

所有动画可中断、可衔接，不排队。离开页面停止不必要动画；从详情返回不重播整墙入场；减少动态效果模式关闭持续背景运动和多余弹性，保留操作反馈。禁止为等待动画而锁住按键。

暂停、错误、选集和设置操作期间不自动隐藏正在使用的控件。加载态允许取消或返回，失败态提供真实的重试和恢复路径。

# 五、持久化与恢复规格

## 5.1 分层存储

Room 承载关联数据、逐集进度、收藏、历史、来源映射与页面快照；DataStore 承载轻量偏好；SavedStateHandle／页面保存状态只保留短期小量恢复标识；图片与可重建内容缓存独立管理。[R01][R02]

数据库内同样区分可重建资料缓存和不可自动删除的用户记录。缓存淘汰不得级联删除收藏或进度；用户记录至少保留足以辨认作品的最小快照。

## 5.2 页面恢复矩阵

| 场景 | 恢复要求 |
| --- | --- |
| 片库 → 详情 → 返回 | 原条件、排序、结果快照、滚动锚点、作品焦点 |
| 收藏／历史 → 播放 → 返回 | 回到原入口和原作品，不跳首页 |
| 顶层页面互相切换 | 每个页面独立恢复，不共享一个“最后索引” |
| 退出应用、重新启动 | 上次稳定页面和上下文，恢复期间不先跳第一项 |
| 上次停在播放器 | 恢复作品、集数、位置和暂停状态，不自动出声 |
| 系统回收进程 | 从本地记录重建，不依赖仍存活的 ViewModel |
| 弱网或断网重开 | 先显示本地记录，网络更新不清空画面 |
| 字号／海报列数变化 | 优先恢复同一作品，不强行恢复失效像素坐标 |
| 来源失效或停用 | 收藏、历史和进度保留；标注当前可用性 |

不自动重放删除动作、订阅确认、过期扫码会话或旧错误弹窗。恢复的是用户现场，不是上次命令。

浏览记忆默认停稳 500 毫秒后写入，离开页面和进入后台时补存；值属初始预算，可经实机数据调整。每次会话保存足够恢复导航来源的有限栈和页面快照，不无限持久化所有临时弹窗。

## 5.3 播放进度

每集独立保存；作品另存当前续播目标。使用独立单调计时执行播放中每五秒检查点，暂停、跳转完成、切集、切线路、离开和进入后台触发关键事件写入。

检查点保存稳定的作品、集、版本标识、有效位置、总时长、状态、会话标识和操作序号。旧回调不能覆盖新会话；按用户操作顺序决定最新记录，不以最大播放秒数决定。

播放器初始化、缓冲和资源重试时的零值不能覆盖有效进度。切集先捕获并保存旧集快照，再建立新集上下文；预加载下一集不算用户开始观看下一集。

最后成功提交是断电或存储故障时的恢复边界。五秒是正常运行时的检查点目标，不宣称所有故障下最多丢五秒。失败必须记录可测试结果并适度提示，不能在界面假报成功。

## 5.4 迁移与备份

旧版 DataStore 导入数据库须幂等，导入记录与迁移标记在目标数据库同一事务中提交；旧文件在核验完成前不删除。来源身份缺失的旧进度放入待关联记录，不猜作品。

旧版从未保存过的逐集历史无法凭空恢复，不能伪造完整历史。数据库迁移失败不自动删库，不启用破坏性迁移兜底。[R04]

手动备份／恢复为本轮增强项：包含必要用户记录与版本化清单，默认排除订阅凭据、网络临时地址和个人设备信息；敏感配置只有明确选择且加密后才允许导出。导入先校验、预览，再事务合并；失败保留原数据。

卸载、系统清除数据、设备损坏需依赖单独备份；应用内部持久化本身不承诺跨越这些事件。[R01]

# 六、继续观看、历史与收藏规格

三者语义独立：继续观看表示尚待续播，历史表示实际观看过，收藏表示用户主动保留。

继续观看以一次确认直接续播；真实开始播放后才更新顺序，浏览海报和详情不算观看。误点后立刻退出不得覆盖旧续播目标。已看完、已看至最新和播放中分别表示；不使用“最后一分钟一律看完”的规则，更不以归零代替完成状态。

完成一集只更新该集，下一集真正开始后再更新续播目标。整部作品是否完结依赖可靠资料；没有完结依据时仅显示“已看至第几集”。

收藏绑定稳定作品而不是可变网址，来源失效也保留；保存失败回退视觉状态并提示。列表默认按用户操作形成的稳定顺序，更新不夺焦点。取消收藏提供短暂可操作撤销，批量清空另作确认。

| 操作 | 删除范围 |
| --- | --- |
| 移出继续观看 | 只隐藏该入口，保留历史和收藏；再次真实播放后重新进入 |
| 删除观看记录 | 删除对应历史和续播状态，保留收藏 |
| 取消收藏 | 删除收藏关系，保留观看记录 |
| 清理图片缓存 | 只删除图片缓存，不删除上述记录或订阅 |

先完成单一默认使用档案，不增加强制账户选择。个人记录离线可浏览；未下载视频不承诺离线播放。

# 七、分类和筛选规格

## 7.1 数据模型不是严格二叉树

保留“先分两大范围”的直觉，底层使用多维属性与关联表。同一作品允许多个类型、多个国家／地区，作品语言与播放版本音轨分开保存。

本计划的分类口径采用“华语／非华语”，按有依据的作品语言划分，另保留内部未知状态；这是对“国内中文／其他内容”需求的明确化建议。普通话配音的海外作品不改写原制作国家和原作品语言；中文字幕不等于中文音轨。

多语言作品带有已确认华语作品语言时归入华语范围并保留其他语言；只有配音标签不能做此归类。信息不足或无法确认的作品留在“全部”，不自动扔进非华语。国家／地区筛选与语言独立。

## 7.2 可组合条件

内容类别、华语范围、国家／地区、类型、年份、排序为独立条件；不同维度同时满足，同一维度多选满足其一。国家选择采用“包含所选制作国家／地区”的语义，允许合拍，不虚构唯一国籍。

电影优先打通这套体验；剧集、综艺、动漫等保留已有有效内容类别，按来源能力接入，不硬造资料不足的空频道。

年份是片库一级筛选入口，不隐藏在国家和类型最深层。支持具体年份、年代、起止年份，去掉 2000 年下限。年代先选十年范围，再选具体年份；年份选择是查询意图，不是库存承诺。

年份默认使用作品原始发行年份口径；来源只给简单年份时保留“来源标注”依据；更新日期、重制资源日期不充当原发行年份。日期解析按字段语义执行，不再统一截前四位。

## 7.3 严格三态匹配

每项判断返回符合、不符合、无法判断。精确结果只包含有依据且满足全部条件的作品；缺字段、冲突未解不混入。空结果不静默放宽条件；“放宽年份”等操作必须由用户明确触发并更新条件摘要。

固定中文标准词表用于统一表达，不直接制造作品标签。“动作／动作片／動作片”在依据明确时归一；“惊悚”不自动等于恐怖，“欧美”不自动等于美国，中文不自动细化为普通话。

## 7.4 范围、数量与排序

区分：正在查询、当前已整理范围无匹配、所查询范围完成、部分来源失败、资料不足、暂时离线。

仅对已去重且严格匹配的集合计数；不知道全库总数就不展示“共 X 部”全量结论。只完成部分索引时，排序明确针对当前已整理结果，不能冒称全库最早或最新。

国家与类型候选使用有证据的资料和来源分类能力生成，不能把未获取当作不存在。候选位置稳定；当前选择不静默清除。年份选择器可接受未收录年份并如实查询，不把它预先标成有库存。

保存筛选组合为本轮增强功能：只保存条件和用户名称，不创建假的推荐榜单。筛选面板保留现有“返回应用并关闭”习惯，并用中文提示；进入后台不自动提交未完成草稿，恢复后仍需显式完成操作。

# 八、统一数据管理与来源适配规格

## 8.1 核心实体与职责

| 对象 | 职责 |
| --- | --- |
| Work / Episode | 稳定作品和剧集身份、基础资料 |
| Source / SourceItem | 稳定来源 ID、来源作品 ID、原始数据与抓取时间 |
| MediaVariant / PlaybackEntry | 配音、版本差异、播放入口及当前可用性 |
| FieldEvidence | 字段原值、标准值、来源、规则版本和冲突状态 |
| TaxonomyMapping | 各源分类到统一类型、国家、语言等的映射 |
| SourceCapability | 查询能力、字段提供情况、分页规则与验证状态 |
| QuerySession / SourceCursor | 查询条件、各源独立游标、覆盖范围、预算与失败状态 |
| WatchProgress / Favorite / BrowseSnapshot | 用户记录和恢复现场 |

数据类型使用显式“未知／来源标注／确认／冲突”等状态，不用年份 0 或空串冒充有效事实。缺失来源 ID 不以片名哈希充当不可冲突的永久作品标识。

字段依据、原始响应和缓存设置容量及保留策略，不无限积累；个人记录不得因缓存回收丢失。来源 URL、凭据和临时播放链接不作为日志中可随意输出的内容。

## 8.2 来源适配与查询规划

首轮优先重构现有苹果 CMS 适配；其他协议独立添加适配器，不在界面堆站点例外。适配器执行结构、格式、类型、编码、字段别名和分页检查。

“能提供字段”和“能在服务端筛选”分开记录。服务端支持过滤时先缩小范围、再本地核对；不支持过滤但有字段时增量建立本地索引；只有详情有字段时按需补充；没有证据时不承诺精确筛选。

成功请求不等于参数有效；一次空结果不等于不支持；一次超时不等于资源永久失效。能力按来源与时间记录、允许重新验证。

各来源和查询会话独立游标；一页本地无匹配不代表后续无匹配；重复页、游标不前进、连续失败要停止消耗并标记未完成，而不是无限循环或虚报完成。

默认采用前台按需加增量索引，不在首次启动全库扫描。后台任务受用户设置、系统调度和设备负载约束；播放期间降低资料整理优先级；支持取消、退避、限流和离线重试。并发上限和容量先以基准测试选择，不宣称存在全设备通用最优值。

## 8.3 作品关联与冲突处理

可靠外部 ID 优先，组合证据用于候选关联；片名加年份不是普遍适用的最终身份。同名翻拍、不同季、不同剪辑版要可区分。无法确认时保持独立，允许后续纠正与拆分，不跨错误关联迁移用户进度。

同一作品合并展示时保留全部来源条目和播放入口。不同字段分别保留依据，不简单“多数源同样说就一定真”，不把不同作品字段拼成一部不存在的作品。

外部资料补全为有条件增强，必须核对匹配、许可与网络可用性。大模型不自动生成作品事实；资料匹配成功不意味着已经有可播放资源。

# 九、资源订阅、首次使用与安全规格

## 9.1 核心路径

首次未配置状态下，设置提供“一键检测并订阅”。用户明确启动后，系统读取维护的可信目录，核验目录与兼容格式，按预算检查候选，保存有效选择，再刷新片库。已启用自动更新后按条件继续维护，不反复要求电视输入地址。

保持手机配置为备用方式，不让它成为全部普通用户的必经步骤。手机配置页全中文，凭据、配对授权和过期处理独立于已删除的设备诊断报告能力。

## 9.2 必须真实表达的状态

检查中、目录为空、网络失败、格式不支持、发现候选、已保存配置、目录可读取、播放入口待验证、当前不可用，不能都写成“已连接／全部可用”。

目录列表请求成功不代表所有影片均可播放。播放可用性为按入口、时间和设备条件的实际状态；不能因为抽测一条视频成功，就给整个来源永久可用标签。

当前默认目录为空。自动订阅流程是必做，默认目录接通是独立前置条件；没有经过审核的目录时交付真实空状态，不内置未经核验的随机地址，不宣称已经完成开箱即看。

## 9.3 配置维护规则

新配置验证完成后原子替换，失败保留最后有效版本。暂时失效不删除个人记录，不自动恢复用户已停用来源，不在正常播放中为了测速切换资源。

目录和导入只允许受支持的声明式数据，不执行下载脚本、远程类库或代码。设置结构、响应大小、超时、重定向和协议限制；远程目录不能借跳转探测私网、环回或链路本地地址。用户主动配置的局域网服务走独立明确授权路径，不被误伤成全部禁用。

订阅目录的来源认证与版本防回退应单独设计，不复用或暴露生产 APK 签名私钥；签名或信任验证失败不能接受新配置。凭据不进入日志、截图、默认备份和源码。

# 十、播放器与增强能力

重试保留最后有效位置，自动切线路有上限；版本或时间轴不能确认一致时不假装无缝，保留原记录并提示用户。播放地址失效时重新解析当前入口，不把短期 URL 当成作品永久标识。

播放内选集定位当前集，已经看过与当前聚焦分别呈现；明确“从头播放”不等于清除整部剧历史。暂停、后台、音频设备变化与生命周期行为按实际播放器事件验证，不以界面显示暂停代替真实暂停。

本轮增强按优先顺序为：保存筛选组合、手动备份恢复、自动连播开关与可取消下一集过渡、睡眠停止、字幕与音轨偏好、可靠数据驱动的追更提示。

睡眠停止仅暂停并保存，不越权承诺关机。字幕音轨只有真实可用时显示；偏好区分全局与作品级，不跨作品乱套。追更只对可靠剧集更新提供提示，不伪造更新、不承诺后台精确时刻执行。

核心接口契约统一定义，避免各页面重新拼接来源数据：

- `CatalogRepository.observeQuery(query: CatalogQuery): Flow<CatalogResult>`：统一查询视图，结果必须包含范围完成度与失败状态。
- `suspend CatalogRepository.loadMore(queryId: String): LoadOutcome`：按查询会话继续，不使用共享页码；取消和预算耗尽有独立结果。
- `suspend PlaybackProgressStore.commit(snapshot: PlaybackSnapshot): CommitResult`：写入不可变快照，检验会话与序号，返回真实持久化结果。
- `suspend BrowseStateStore.save(snapshot: BrowseSnapshot): CommitResult` 与 `suspend load(contextKey: String): BrowseSnapshot?`：按上下文独立恢复。
- `suspend FavoritesStore.setFavorite(workId: String, selected: Boolean): CommitResult`：幂等设置，不依赖 UI 盲目翻转。
- `SubscriptionManager.refresh(request: SubscriptionRefreshRequest): Flow<SubscriptionState>`：真实分阶段状态，失败不覆盖有效配置。

以下是这些契约的最小共同字段；T02 将其转为唯一类型定义并补齐序列化，不由各任务分别发明同名类型。

| 契约类型 | 最小字段或结果语义 |
| --- | --- |
| CatalogQuery | queryId、contentKind、languageScope、countryIds、genreIds、yearStart、yearEnd、sort、enabledSourceIds；无年份界限用 null，不能用 0 冒充年份 |
| CatalogResult | queryId、items、coverage、failedSourceIds、unknownFieldCount、knownMatchedCount、hasMore、snapshotRevision；总量未知用 null，coverage 不能由 items.isEmpty 推导 |
| LoadOutcome | Loaded、Complete、Partial、Cancelled、Failed；Partial 表示预算或部分失败导致未完成，不表示没有匹配 |
| PlaybackSnapshot | workId、episodeId、variantId、sessionId、operationSequence、positionMs、durationMs、watchState、capturedAt；未知总时长为 null，位置不得为负 |
| CommitResult | Committed、RejectedStale、Failed；只有 Committed 表示目标存储提交成功，RejectedStale 不覆盖现有值 |
| BrowseSnapshot | contextKey、route、parentRoute、query、resultRevision、focusedWorkId、anchorWorkId、relativeOffset、savedAt；焦点与锚点允许为空且有明确回退 |
| SubscriptionRefreshRequest | reason、catalogId、enabledSourceIds、consentRevision；不得把下载到的目录自身当作用户授权 |
| SubscriptionState | Idle、Checking、CatalogEmpty、CandidatesFound、Saving、Configured、Failed；Configured 只证明配置提交，不证明所有视频能播放 |

稳定 ID 使用内部不透明标识，不以标题、列表位置或可变地址作主键；国家、语言和类型集合使用规范 ID，中文名称由映射展示。取消信号必须向上传播，不统一转换成网络失败。数据和查询层完成后，经兼容适配再替换旧接口，避免旧新路径同时写用户记录。

# 十二、质量预算与验收规则

## 12.1 功能与数据硬门槛

所有关键恢复、筛选、迁移和遥控器用例必须通过。数据丢失、误关联导致串进度、精确筛选混入已知不符结果、焦点死路、重复确认触发多次导航均为阻断缺陷。

清缓存只影响缓存；网络与来源错误不清用户记录；迁移失败不删库；未接通资源不显示成功；生产资料不包含演示伪数据。

## 12.2 性能初始目标

以下是本项目拟定目标，不是当前性能承诺。M00 选定并记录低配置参考设备与较新参考设备后固定测量方法；未达标必须优化或明确缩减特效，不能悄悄降低标准。

| 项目 | 初始目标 | 测量边界 |
| --- | --- | --- |
| 遥控器本地焦点反馈 | 按键分发至首个反馈帧第 95 百分位不超过 100 毫秒 | 不含遥控器硬件传输；网络请求不阻塞反馈 |
| 本地筛选 | 10,000 条有界元数据测试集，第 95 百分位不超过 200 毫秒 | 参考设备、缓存条件、冷／热查询分别记录 |
| 已缓存页面返回 | 目标内容可见且焦点恢复第 95 百分位不超过 300 毫秒 | 已有数据，不混入远端请求耗时 |
| 冷启动恢复 | 有本地快照时到首个可操作画面第 95 百分位不超过 2 秒 | 参考设备与测试包配置固定；首次迁移另测 |
| 界面渲染 | 60 Hz 参考设备以约 16.7 毫秒帧预算为目标，预定交互脚本卡顿帧比例目标低于 1% | 非调试、接近发布构建；记录测量工具口径 |
| 稳定性 | 每台参考设备两小时核心路径混合循环无崩溃、无无响应、无焦点失效 | 使用合法测试媒体；并检查内存是否持续增长 |
| 播放检查点 | 正常播放每五秒尝试保存，关键事件立即排入持久化 | 断电／I/O 故障仅保证已成功提交记录 |

60 Hz 帧预算与非调试、较慢设备验证依据 Android 官方性能指南；具体百分位与目标比例为本项目提出的验收预算。[R05]

界面帧率、视频解码帧率、网络首帧和缓冲分别记录，不能把所有等待都归为动画问题。容量与内存预算在参考设备上测量后固定，缓存使用有界策略，不硬编码未经测量的“适用所有电视”上限。
