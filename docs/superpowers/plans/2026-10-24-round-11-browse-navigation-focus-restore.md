## Global Constraints

- No production release activation, signing, package/version change (`0.9.8`/code `18`), ABI expansion, minSdk/targetSdk change, update asset/tag edit, repository visibility change, push, merge, rebase or install on a physical/personal device. Keep production signing frozen.
- Ordinary build with `cinema.browseRestoreProbe` **OFF by default** retains pre-R11 app routes, data path, legacy `DataStoreBrowseStore` and writer authority; Release, bundle/publish and invalid variant combinations must reject any ON request *before* build side effects. Work with the existing `cinema.storageTestArm64`, `cinema.playbackRoomProbe`, test-ownership/legacy-handoff guards; do not weaken or bypass them.
- Candidate runtime ON requires both a fully verified Debug/DebugAndroidTest variant **and** explicitly authorized, owned, disposable no-legacy-data test profile. If any required flag, profile, writer quiescence or database validity is uncertain, fail closed. Do not double-write browse or playback state to legacy and Room.
- Use only synthetic test works, local deterministic catalog listings and clearly named test-only query fixtures. No public CMS, default media catalog, automatic source scan, user data import, remote link or fallback to a broad unfiltered query. Do not ship synthetic posters, movies or fixtures to ordinary end users.
- Full query parameters, country/language/genre/year/sort and source scope must round-trip; no reversion to legacy filter defaults. Work IDs are opaque/stable, not title+year, item index or URL. A list refresh cannot relink favorites, play progress, source captures or routes.
- Preserve meaningful differences between **focus**, **selection**, **scroll anchor** and **navigation origin**. Do not auto-focus the first item while a known saved target is loading; never show focus on more than one element in the active scope. Never resume playback with unsolicited audio on navigation restore.
- Navigation/focus restoration is a cancellable *request*, not an unconditional delayed command. Require current route generation, matching query/result context, data presence and actual layout readiness. Explicit user D-pad/OK/Back input takes precedence, invalidating pending restoration. Modal active focus traps background; closing returns focus to invoker when still present.
- Persist every top-level context independently; use `BrowseSnapshot` `contextKey` plus exact query, stable work/anchor IDs, `relativeOffset`, `resultRevision`, route and parentRoute. A bounded return chain must not turn library→detail→player→back into an arbitrary home jump; no endless stack or persisted destructive dialog.
- Save when focus is stable (master's initial 500ms debounce), immediately on route leave/background where safe; report durable save failures, retain retry status, and avoid a late debounce write from the departed screen overwriting the newer context. Do not promise arbitrary power-loss durability beyond last acknowledged commit.
- Distinguish observed-null/target-not-loaded from *proven removed*. If current strict query is partial and the target is not in the current page, continue bounded query/recovery or yield an honest pending state; do not claim removed, silently relax conditions, or issue unbounded fetches. For truly removed content, fallback **nearest valid neighbor → current row entry → page default control**, without unrelated cross-row jump.
- All authored UI strings, state/error hints and accessibility labels in Simplified Chinese; no in-app brand title/watermark or misleading counts. This is a focused test UX; final original icons, whole-screen redesign, diagnostics deletion and long-term motion polish remain T02/T10–T12.
- Avoid any Room schema change if actual v5 storage suffices. If and only if a new persisted navigation pointer/stack entity is necessary, add real explicit **v5→v6** migration, generated `6.json`, test seeded v5→v6 and original 1→5 lineage; preserve prior schema files byte-for-byte and prohibit destructive fallback. Never fake migration evidence.
- Do not mark all T08, M02/M04, A03/A04/A05/A19 passed from a synthetic native slice. API30 ARM64 AVD is not API24/ARMv7 hardware or real physical remote testing. No claims that production navigation currently uses the new Room mechanism.

## Review Focus — user-visible failures to actively test

1. **Late restore steals focus:** user presses D-pad/Back while a remote/Room snapshot is loading; pending focus request must be cancelled, never move the user's later focus. Native test: `user_input_cancels_late_focus_restore`.
2. **False first-item landing:** process restart/return while target is on a later page; no focused default first poster flashes before the saved target becomes layout-ready. Native test: `deep_list_waits_for_anchor_and_layout`.
3. **Lost origin or query:** library/favorites/history must not share a last-index field; detail/player return restores the exact saved filter, stable target and true origin. Native test: `return_uses_origin_context_not_home_default`.
4. **Wrong fallback under partial coverage:** absent work ID while query is still partial is not proven deletion. Bound further lookup and use the specified fallback only when truly unavailable, without silently relaxing filters. Native test: `incomplete_result_does_not_prove_target_removed`.
5. **Cancellation/write race:** delayed save from older route or a cancelled process rehydration does not overwrite new selection; room close/reopen preserves successful snapshots. Native test: `stale_route_write_cannot_replace_newer_context`.
