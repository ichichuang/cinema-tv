# 维护者决定与未通过门槛

记录日期：2026-10-23。以下为当前决定，取代此前 Draft、未合并和目的地未选定的阶段记录。代码合并、历史清理、正式签名、设备迁移与 Public 公开分别验收。

## 已确认并实施的范围

- 最终只保留 `ichichuang/cinema-tv` 一个长期 GitHub 仓库，唯一分支为 `main`；源码及 `update/version.json`、`update/sources.json` 都放在 main，正式 APK 仅使用该仓库 GitHub Releases。
- PR #1 已合并。整改分支的全部 159 个文件已与 main 核对：158 个 blob 完全相同，唯一差异是 main 新增的决策记录，原文保留。已删除本地及远端 `security/remediation`；旧 PR 引用和受污染历史仍存在，分支删除不是历史净化。
- 维护者在本次会话明确批准 Apache License 2.0，并确认代码及六张图片的再分发权；根 [LICENSE](../LICENSE) 已采用 Apache 官方原文。[图像权属记录](ASSET_PROVENANCE.md)记录声明范围，第三方材料仍依各自条款处理。
- 旧仓库 `cinema-tv-releases` 只作临时兼容桥。已安装 0.9.8 的默认地址不会被新源码改写；迁移和旧用户影响获准前，不写入、不删除该桥。
- Gradle 正式签名冻结、生产认证关闭；普通 push/PR CI 无生产凭据、无 APK 上传、无发布。生产 transport、固定信任根、DI 和启动恢复未经批准不得接入。
- 本轮授权的是仅源码公开：离线恢复、干净历史、许可、扫描、精确提交 CI 与受控权限是源码门；生产密钥、电视兼容及 APK 发布另行验收，不作为仅源码公开的前提。仅源码公开仍不关闭签名事件。

## 已有证据可复用的范围

[迁移夹具](../tools/migration-fixture/README.md)与其测试报告记录官方 API 30 镜像的 7 个独立场景、21 次实际安装（17 成功、4 次签名不兼容拒绝），UID 与合成数据保持；独立认证 harness 有 9 项限定运行时检查。应用与迁移实现未变，因此本次不重复矩阵。它不证明生产 APK、厂商电视、ARM32 原生库、真实用户数据/播放、API 24–27 或掉电恢复已验收。

本次 main 基线验证为 Python 40、夹具 JVM 3、应用 JVM 75（0 failure/error/skip），完整 debug 与 unsigned release、两种 Lint（各 0 error、20 warning）、99 个 Gradle 任务全部执行；显式签名请求按冻结拒绝。后续新增导出/发布预检测试、最终源码树和 exact-SHA CI 的实测结果保存于私有交付证据，不把历史计数当最终计数。

## 仍需要维护者输入或外部条件的事项

| 操作 | 当前缺失的具体前提 |
| --- | --- |
| 销毁旧历史 / 同名重建 | 维护者本轮再次确认“尚未建立”独立离线目的地。仍需独立故障域的加密副本、恢复资料保管与从该副本实际恢复的证据；本地加密恢复成功不能替代。通过后，删除旧仓库和同名 Private 重建仍须即时明确确认。 |
| 生产 APK 与元数据信任 | 分别指定两类私钥责任人、独立保管/审批和离线恢复；批准元数据公钥及替换 APK 证书的公开指纹、独立首次安装渠道与核对责任人。不得在聊天中提供私钥或口令。 |
| 生产认证集成 | 审批 [候选协议](AUTHENTICATED_UPDATES.md)关联的 transport、固定根、DI、真实安装状态恢复、replay/时钟失败和首次安装方案，然后才实现及另行激活。 |
| Android 11 电视迁移 | 明确唯一设备、允许操作及验证时段；正常系统验签下保持包名、UID、设置、来源、进度，验证原位/后续更新、旧钥拒绝、启动和播放。历史设备地址不算本次授权。 |
| API 24–27 | 明确不支持 lineage 的旧平台政策及数据影响，不静默提高 minSdk、不卸载清数据、不以受损旧钥续签伪装恢复。 |
| 独立 main 保护与安全扫描 | 私有仓库的分支保护/rulesets 403 属于当前套餐限制。先完成安全 Private 重建与 CI，备妥规则请求，单独获准 Public 后立即安装并读回规则、安全扫描和私密漏洞报告；必需控制失败时回到 Private，不假报上线。 |
| 仅源码 Public 公开 | 离线恢复、干净历史/引用、Apache-2.0 与通知、扫描、冻结隔离、精确提交 CI 通过后，再请求最终 Public 确认；无生产 APK 下载，电视迁移和生产签名不在本轮执行范围。 |
| 删除旧兼容桥 | 先完成安装迁移和必要 APK 的本仓库 Releases 转存/读回验证，处理剩余旧客户端影响，最后另行确认不可逆删除。 |

不新建长期存档仓库或官方开发分支。未来贡献由贡献者 fork 发起 PR，经过独立审阅与 CI 后合入官方 main；规则配置及套餐阻断见 [公开准备](OPEN_SOURCE_READINESS.md)。
